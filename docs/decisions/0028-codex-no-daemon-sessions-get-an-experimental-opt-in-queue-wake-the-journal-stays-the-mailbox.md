# ADR 0028 — Codex no-daemon sessions get an experimental opt-in queue wake, the journal stays the mailbox

- **Status:** Provisional (council 2026-11-10, revised after the chair's critique, a Codex adversarial review and the chair's final precision fixes the same day; operator consent rulings (a) to (d) recorded 2026-11-10; design only, the operator has not approved a build, gated on the feasibility probes and an isolated prototype)
- **Date:** 2026-11-10
- **Deciders:** operator (consent rulings 2026-11-10; build approval pending) + Claude + council (five advisors, one of them Codex)
- **Implementation:** planned, not built. No hook command, no claim file, no `mailboxed` state, no `MailSignal`, no wake generation record and no SQLite driver exist in the code.
- **Context source:** issue #112; [change plan](../plans/codex-no-daemon-queue.md); council record of 2026-11-10

## Context

A Codex session started with `codex --no-daemon` runs a private app-server inside its own process, with no socket CrossTalk can dial. It can send and pull messages but cannot receive them: `Register` binds it with an empty endpoint, `Inject` returns `ErrNoEndpoint`, a send is `unreachable` and an ask is `rejected/no_endpoint`. The supported workaround, a dedicated app-server plus `codex --remote` (`docs/setup.md`), has never been run live.

The only inbound surface such a process has is its local queue, `~/.codex/queue_1.sqlite`, table `queued_items`, which holds the user's queued prompts and which a watcher in the Codex process dispatches into the thread. Since a 2026-08-17 Codex migration, revision triggers make an external insert visible to that watcher. Codex source at tag `rust-v0.167.0` (`codex-rs/ext/queue/src/service.rs`, read, not run) shows a 10 s watcher that skips Running, Interrupted, Shutdown and NotFound threads, deletes an invalid or non-user row and continues, and removes a row when Core accepts the turn, before any proof the model fetched anything; the queue holds at most 100 items. Live manual inserts on 0.167.0, per trial: into an idle thread, a row carrying a plain operator-requested "hello world" prompt (not the fixed mailbox notification) started a turn; into an idle advisor thread, a fixed wake row started a turn in which the model called `receive_message` and answered with `send_message`, not `reply` (the only full nudge → pull → answer evidence; the row's removal was verified for this trial); into a busy thread, two rows stayed in the queue (one checked at 15 s, both still present later) and the messages were pulled by hand, so that trial shows persistence and a readable mailbox, not dispatch. The queue has no external-write contract and a dispatched row is a user turn. Whether a running daemon competes for the same thread is a hypothesis with no evidence; the writer lock gates ownership.

ADR 0007 keeps peer text out of operator input and says no subprocess queue is used; ADR 0004 keeps peer text out of instructions. ADR 0012 defines `mailboxed` and `collecting` for a harness with no push channel, but is unbuilt. Today the receiver journals a dispatch outcome only after `Inject` returns, and the latest outcome record wins; the MCP server serves concurrent calls, including repeated calls for one thread, and one process may serve several threads (ADR 0006). `receive_message` never returns `accepted` or `queued` entries, so a wake that pointed at a `queued` entry would point at nothing the model can pull.

A SessionStart hook fires at the first turn, not at launch (measured), and the shim starts about 1 s after Codex. An unprompted tab fires no hook. Today a session is unreachable until its own first CrossTalk call, and nothing can wake it to make that call. The owning Codex process has `~/.codex/thread-writer-locks/<thread>.lock` open (whether it holds the lock is unmeasured); the shim's parent is that process; pooled daemon shims have a different parent. The hook's `session_id` is self-asserted stdin text. ADR 0004 accepts that the same-user credential model is no isolation from hostile same-user processes.

## Decision

Gate order: first raw Codex lifecycle and hook evidence (plan step 0), then an isolated prototype of the unbuilt mailbox and claim semantics (step 0b), then product implementation only after the operator approves the plan. If those pass and the operator approves, a `--no-daemon` session may receive through a queue wake, built as follows. Until then nothing is built.

1. **Experimental and opt-in.** One host-wide setting, off by default, turned on by one install flag, with no per-session or per-sender switches in v1 (operator ruling (a), 2026-11-10), never described as production-ready. The supported routes (daemon, dedicated app-server) are unchanged and named first in the docs.
2. **The journal is the mailbox, and mail is pullable before any wake.** The chain order (authenticate → dedupe → hop-chain → policy → `Inject` → resolve) is unchanged. The Codex adapter's `Inject` writes nothing external and returns `mailboxed`; the receiver records `mailboxed` and only after that commits calls the adapter's optional `MailSignal` (ADR 0012's extension point), which alone writes the wake row. Mailbox states are monotonic (`mailboxed` → `collecting` → `accepted` or `unknown`); a late or replayed outcome never moves an entry back. ADR 0012's states are reused and built harness-neutral: `receive_message` returns `mailboxed` entries and marks them `collecting` with a collection token. An entry is settled `accepted` only on causal evidence of receipt: a `reply` naming it, a later pull whose `after` cursor covers it, or a later call echoing the token in an optional `ack` argument. Another call, concurrent or not, is not evidence, and a call from another thread never is. No evidence within a bound (and at exit or replay) means `unknown`: readable, unresolved, never re-woken; CrossTalk never forces a tool call only to acknowledge. Nothing is `accepted` before handoff, and `queued` is not reused. Row removal by Codex is never delivery evidence.
3. **The wake carries no peer text.** One row with a fixed sentence naming `receive_message` on server `crosstalk`: no sender, no count, no message id, plus a stable CrossTalk wake id in the row's client id field. The body arrives as tool output with the existing notice and stays data under the skill, although the wake itself is user-role. The paid user-role wake turn is a named exception to ADR 0007 and ADR 0004, allowed narrowly: fixed text only, at most one open wake per thread, only while the setting is on, only for `immediate` sends from verified senders (operator ruling (b), 2026-11-10).
4. **Persisted wake generations, bounded writes.** Each wake is a journal generation per thread, recorded before the action it names: `pending`, `queued`, `admitted` (row seen gone, no pull yet), then closed as `collected`, `unknown` or `failed`. A new row is written only when no generation is open, in one immediate transaction at `MAX(queue_order)+1` with a bounded busy retry; a thread at the queue cap gets no row. Ambiguity resolves toward fewer paid turns: `admitted` with no pull within a bound, or `pending` on replay with no row found, becomes `unknown`; replay and bind never write a row; only a newly arriving message opens the next generation. No promise of exactly-once or of one wake per N messages. A pull that leaves entries behind says so, so one wake drains several pages. There is still no message rate limit (ADR 0014); only redundant wakes are bounded.
5. **Fail closed, revalidated per write.** Write only when the file already exists, its table layout, queue migration checksums and revision triggers match a pinned set, and the parent Codex version is on a tested allowlist. The file's identity and schema are re-checked inside the write transaction, so no cached result survives a replaced or migrated database; the version is cached only per (parent pid, start time) and only while the parent's mapped executable is the file at its path. Otherwise `unreachable` with a hint naming the supported route, and existing entries stay pullable. Never write when any app-server hosts the thread.
6. **Mutually exclusive routes; who never wakes.** Checked first, as a guard: any earlier attempt for the message, on any route, ended `unknown`: `unknown`, no resend, no fallback to user input and no new wake, even when a host now exists, so one envelope never enters both paths. Otherwise exactly one of: exactly one app-server host and no owner-proven claim: unchanged. No host, unambiguous ownership, no queue capability (setting off, no owner-proven claim, gate fails): `unreachable`, asks `rejected/no_endpoint`. Capability present and `next_turn` or an unverified sender: `mailboxed`, no wake. Capability present, `immediate`, verified sender: `mailboxed` and a wake. Two or more candidate hosts, or ambiguous ownership (a host and an owner-proven claim, or owner-proven claims from more than one process): `unreachable`, asks `rejected/no_endpoint`. An interrupted or paused thread stays paused.
7. **Asks.** Once the feasibility probes and the live acceptance run pass, an ask to a session with queue capability is accepted in state `mailboxed`, route open and deadline armed; until then it stays `rejected/no_endpoint`.
8. **Registration and ownership.** Registration is its own must-pass goal: a session is receivable before its first message is sent to it, and once SessionStart has fired it no longer depends on the session's own first CrossTalk call (making that call a precondition would repeat today's circular dependency). A stateless SessionStart hook hands a claim to the owning shim through an authenticated exchange and leaves it durably in a 0600 file. The shim registers from the claim only when four proof obligations hold. Target: the shim's own parent owns the thread's writer lock; this proves the thread exists and is owned, not that the claim came from its hook. Live origin: the claim's sender pid is taken from the transport (the socket peer credential) and its actual ancestry is verified to reach the shim's parent; a pid or `CODEX_THREAD_ID` in the claim body is never used. Durable claim: a 0600 file written before the shim listened cannot be tied to its writer, so it stops other users only; a hostile same-user process can forge it, which ADR 0004 places outside the trust model, and the only bound is that it can bind no thread but one the parent owns. Lock ownership: the check shows the parent holds the lock, not merely has the pathname open; if Codex's lock cannot be read that way cgo-free, the proof fails closed. Claims and records are per (harness, thread): one process may serve several threads, a call carrying another thread's `_meta.threadId` binds per request (ADR 0006) and never revokes another thread's claim. A claim is revoked for its own thread only, when the proof fails on recheck or a claim for the same thread arrives from another process. Without the proof the row is discovered and unbound only, and the claim never unlocks a queue write, an ask, a name pin, a `claim` or a `command` target. Whether the proof is sufficient is pinned by tests and the live acceptance run, not an operator question. An unprompted tab fires no hook; discovering it from parent-owned locks is a separate probe and not promised.
9. **Honest sender state.** The sender sees `mailboxed` with a hint (best effort, idle-only, a 10 s watcher interval at 0.167.0 per source, not a deadline), never delivered; `list_agents` shows the row's delivery mode. Crash windows across the two stores and the queue-to-daemon switch after a resume are specified in the plan, section 3.6.
10. **Small footprint.** No general SQLite abstraction; a cgo-free driver, so the signed static release holds (ADR 0015, 0017). No upstream Codex issue or request without the operator.

When built, ADR 0007 is amended in place: the fixed-text user-role wake is a named exception, and "no subprocess queue" is narrowed to "no peer text in a queue".

## Rejected alternatives

- **Peer text in the queue row.** Gives peer text operator authority (ADR 0007, 0004) and would replay with the row on resume.
- **Returning `queued` for a written row.** The pull hides `queued` entries, and a committed row says nothing about the model.
- **On by default, or production status now.** One full nudge → pull → answer on one version, and no observed dispatch for a busy thread; the interrupted, resumed, compaction, crash and ownership-transfer cases are untested; each wake is a paid turn.
- **A general wake primitive for every harness.** Premature before one harness's queue lifecycle is measured.
- **Trusting the hook's claim alone.** Its `session_id` is self-asserted; any same-user process could write a claim for a thread. The owner and lineage proof is the minimum.
- **Requiring the session's first `tools/call` before the queue route opens.** Circular: nothing can wake the session to make that call.
- **Daemon-only (do nothing).** Leaves #112 open on an untested workaround. It stays the default, and the answer if the probe or the operator says no.
- **Deleting or rewriting rows CrossTalk did not write, or unknown rows.** Never. Deleting CrossTalk's own stale wake rows is deferred from v1 (operator ruling (d)).
- **Writing the wake from inside `Inject`.** `Inject` returns before the receiver records `mailboxed`, so Codex could take the row and the model pull before the entry is visible, and a crash in that gap recovers as `unknown`.
- **Settling on the next bound call.** Codex issues tool calls concurrently; a `list_agents` alongside the pull says nothing about what the model read, and settling on it can mark unread mail `accepted` and hide it from later pulls.
- **Revoking a claim on any differing `_meta.threadId`.** One process may serve several threads; that would break per-request identity (ADR 0006) for valid subagent threads.
- **Caching the gate per process.** A database replaced or migrated by another Codex process, or a binary upgraded under a running parent, would pass a stale check.
- **A broad SQLite layer or a cgo driver.** More surface than one guarded insert needs; a cgo driver breaks the static signed release.

## Consequences

- The route depends on a private Codex store and on observed, not contracted, behaviour. Each Codex minor needs the probe re-run before the allowlist grows; until then the gate turns the route off.
- Each wake costs a model turn and is visible to the operator as a user turn.
- A crash, turning the setting off, or a Codex upgrade can leave a CrossTalk wake row in Codex's database; a later resume may fire it once. The wake is harmless by construction (it only asks for a pull), not by cleanup. CrossTalk writes no new row in those cases, and the user docs say so (operator ruling (c), 2026-11-10). v1 deletes no wake row; stale-row cleanup is deferred (operator ruling (d), 2026-11-10).
- Without a reply, a covering cursor or an echoed token, collected informs end `unknown`; that is the honest state, not a defect.
- A lost wake leaves mail pullable but unannounced until the next arrival or a manual pull.
- An unprompted `--no-daemon` tab stays unreachable; the docs must say so.
- Building it also builds ADR 0012's shared `mailboxed` contract, which changes `receive_message` (cursor, token, optional `ack`) and the state list in design §8, adds the post-resolve `MailSignal` step, narrows ADR 0012 item 3 to causal settlement, and needs edits to design §3, §5, §6, ADR 0007, `docs/setup.md`, the FAQ and AGENTS.md.
- Implementation commits carry `Provisional-ADR: 0028`.

## Operator rulings (2026-11-10)

The operator asked for this experiment; whether to write the queue at all is decided by the probes, not asked. Flag naming and the state machine are engineering choices. The consent questions were decided on 2026-11-10 (plan section 7):

- (a) One host-wide setting, off by default; no per-session switches in v1.
- (b) Paid user-role wake turns are allowed narrowly, as an exception to ADR 0007/0004: fixed text only, at most one open wake per thread, only while the setting is on, only for immediate sends from verified senders.
- (c) A wake row already written may fire once after disable, upgrade or resume; CrossTalk writes no new row; the user docs must say so.
- (d) v1 deletes no wake rows; stale-row cleanup is deferred.
